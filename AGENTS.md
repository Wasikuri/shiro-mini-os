# AGENTS.md — Shiro Mini OS: handover notes for the next Muse

Read this first. It is the orientation sheet for taking over this project cold:
what it is, how to build and test it, the conventions the user has set, and the
known limits as of the current version. The long-form history and feature
documentation live in `README.md` (Japanese); this file is the operational one.

## What this project is

- A from-scratch hobby OS for i386 PCs: original kernel, original filesystem
  (SHFS), original TCP/IP stack, original GUI/window manager — no Linux/Unix/DOS
  code lineage, not a fork or distribution of anything.
- Boots via GRUB (Multiboot1 + Multiboot2) from a hybrid BIOS/UEFI ISO; runs in
  QEMU and VirtualBox; preemptive multitasking, paging, ring-3 user programs.
- Ships a graphical web browser whose engine is named **Tabby** (HTML parsing,
  layout, rendering and the CSS subset are all in-house; not Blink/Gecko/WebKit).
- The user (Koji) directs at stage level; implementation and verification are
  done by Muse. Development policy is in a section below — follow it.

## Build and run

Requirements on a normal Linux host: `gcc` (with 32-bit freestanding support),
`binutils`, `grub-mkrescue` (on Debian/Ubuntu also `grub-efi-amd64-bin` —
without its x86_64-efi modules the ISO silently loses its UEFI half),
`xorriso`, `mtools`, `python3` (plus PIL, used
only to regenerate `assets/wallpaper.jpg` when the checkout lacks it), and QEMU
(`qemu-system-i386`; the `uefi` harness group also needs `qemu-system-x86_64`
and OVMF at `/usr/share/qemu/OVMF.fd`).

```sh
make            # builds kernel, sample apps and shiro-os.iso (default target)
make run        # boot the ISO in QEMU with disk.img attached
make clean
```

## Test harness — read this before running anything

```sh
python3 tests/qemu_test.py          # the default set (22 checks)
python3 tests/qemu_test.py web      # one group
```

- Groups: `fs`, `gui`, `tls`, `apps`, `jstest`, `web`, `uefi`, plus individual
  default-set names (`boot`, `help`, `ps`, `date`, `dhcp`, `net`, `shell`,
  `run`). **"default" is NOT a group name** — the no-argument run is the
  default set.
- Green baselines at v1.0.1: default 22/22, fs 8/8, gui 23/23, tls 4/4,
  apps 10/10, jstest 1/1, web 40/40, uefi 5/5.
- **Serialize all harness runs.** The harness kills stray QEMU processes at
  startup; parallel runs kill each other's guests.
- **Shared-disk contamination trap:** the harness reuses `tests/work/disk.img`,
  which persists guest settings (notably `res=WxH`). Geometry-sensitive `gui`
  checks can fail on a leftover disk (e.g. persisted 1280×1024) while passing
  on a pristine one. When in doubt, delete `tests/work/` and rerun before
  concluding a regression.
- **Live-site checks can flake.** Some checks reach real sites (example.com,
  Google); on a restricted/sandboxed egress they intermittently fail
  (per-host stalls and drops are environmental, documented in README).
  Rerun the single group in isolation before treating a live-check failure
  as a regression.
- The harness serves `tests/testsite/` over local HTTP and uses
  `tests/echo_server.py` for form round-trips; `tests/tls/` holds a local
  TLS test server setup.

## Source map (one line per major file)

- `src/kernel.c` — boot, shell, built-in commands, version banner/`version`.
- `src/boot.s`, `src/interrupt.s`, `src/cpu.c` — entry, IDT stubs, GDT/IDT/PIC/PIT.
- `src/sched.c` — preemptive scheduler/tasks. `src/mm.c` — paging + heap.
- `src/fs.c` — SHFS filesystem on ATA PIO (flat, 64 entries).
- `src/net.c` / `net.h` — e1000 driver, Ethernet/ARP/IPv4/ICMP/UDP/DNS/TCP,
  HTTP(S) download + POST, User-Agent string.
- `src/tls.c` / `tls.h` — BearSSL wrapper (SNI + hostname verification always
  on). `src/tls_anchors.h` — generated trust anchors (see `third_party/`).
- `src/gui.c` — VBE (DISPI) / GOP framebuffer backends, page flipping, window
  manager, desktop, exported `gfx_*` drawing layer used by the browser.
- `src/browser.c` — the Tabby engine: HTML/CSS-subset layout, forms, images,
  tabs/history, page-JS glue.
- `src/apps.c` — `install`/`apps`/`run`/`uninstall` registry.
  `src/exec.c` — ELF loader for ring-3 apps (syscalls: write, read char, exit).
- `src/mb2.c` — Multiboot2 parsing incl. the GOP framebuffer tag (type 8).
- `src/rmtrap.s` — real-mode trampoline for BIOS calls (VBE mode-info query).
- `src/jstest.c`, `src/js_shims.c`, `src/js_math.c`, `src/libc_shims.c` —
  Duktape embedding and its freestanding shims.
- `src/user/` — sample ring-3 apps (`hello.c`, `calc.c`, linker script).
- `src/font8x16.h` — embedded 8×16 font. `src/os.h` — shared kernel header.
- `third_party/` — permitted OSS (below) + `mozilla-cacert.pem` and the split
  `certs/`; anchors are regenerated by `third_party/make_anchors.py`.
- `tools/make_wallpaper.py` — synthesizes `assets/wallpaper.jpg`.
- `tests/qemu_test.py` — the harness; treat it as the executable spec.

## Development policy (set by the user — do not drift from it)

- **From scratch by default.** Do not adopt open-source libraries for
  convenience. OSS is used only where the user explicitly granted a per-stage
  exception. Granted so far: **BearSSL** (TLS), **Duktape** (JavaScript),
  **stb_image** (image decode), the **Mozilla CA bundle** (trust anchors).
  GRUB (bootloader) and GCC (toolchain) are infrastructure, not code adoption.
  If a new library seems right, ask the user first.
- **Every stage is verified by the lead Muse before delivery**: re-run the
  relevant harness groups on the shipped ISO and eyeball the screenshots
  personally; never deliver on a subagent's word alone.
- **Replies to the user are kept short** (standing token-saving preference);
  report failures plainly, with the practical alternative.
- Hard spots get at most ~3 distinct approaches, then a documented fallback
  or an honest scope cut — protecting the green regression beats any single
  feature.
- New stages start only with the user's go-ahead; within an approved stage,
  proceed without re-confirming.

## Current status and known limits (v1.0.1)

- **Versioning:** the version string lives in `src/kernel.c` (banner and
  `version` command), `src/gui.c` (GUI Info window), `src/net.c`
  (`User-Agent: ShiroMiniOS/<ver>`), `README.md`, and harness expectations in
  `tests/qemu_test.py`. Bump all of them together.
- **UEFI/GOP:** the hybrid ISO boots end-to-end under OVMF via Multiboot2,
  but true GOP is **not active**: GRUB's EFI multiboot2 loader emits no
  framebuffer tag (type 8), so under UEFI the GUI uses the VBE/DISPI backend.
  The tag-8 GOP parser/backend is implemented and activates if a loader ever
  supplies the tag. The known route to real GOP is a custom EFI-stub loader
  that reads GOP before ExitBootServices — **not started; needs the user's
  explicit go-ahead.**
- **VirtualBox:** v1.0.1 reads the VBE mode-info `LinBytesPerScanLine` and
  uses pitch×height as the page size (fixes the sheared desktop on
  VirtualBox's padded scanlines; QEMU is unaffected, its pitch is width×4).
  Recommend the **VBoxVGA** controller (VMSVGA is not the DISPI target).
  Resolution never auto-fits the host window — that would need a
  Guest-Additions/VMMDev driver the OS does not have; `res` picks fixed
  modes. Final on-hardware confirmation is the user's VirtualBox retest.
- **Browser (Tabby) limits:** content pages (articles, Wikipedia, blogs,
  search results) are the target; **JS-app/SPA sites cannot work** (no
  timers, event handlers, or dynamic DOM). Layout is a simple flow model
  (no float/flex/grid/absolute positioning). CSS is the README-listed subset
  only. Images load **sequentially and synchronously** during page load.
  Each image fetch is capped at **5 s total** (DNS + connect + headers +
  body, NEXT-STEPS P0); on timeout the alt text is shown and the rest of
  the page continues loading.
  Page cap 256 KB / 1024 lines. In-memory cookie jar only (cleared on GUI
  exit). Full limits list is in README's browser section — keep it honest
  and current when you change behavior.
- **Security posture (state it plainly if asked):** ring-3 app isolation and
  verified TLS exist, but there are no logins/passwords, no FS permissions,
  no disk encryption, no ASLR/stack canaries; the hand-written parsers are
  unfuzzed; entropy is weak on CPUs without RDRAND.
- App ABI: installed apps are ELFs built for this OS only (3 syscalls);
  ordinary Linux/Windows binaries do not run. A Linux-compat layer, DOS
  support, and an EFI-stub loader were discussed with the user as possible
  future stages — none are approved or started.

## Repository hygiene

- `webterm/` (a local web-terminal helper) is **git-ignored and must never
  be committed**: it contains an access key and a session disk image.
  The same goes for all `*.img` files, `tests/work/`, `build/`, `isodir/`
  and `*.iso` — sources and docs are published, artifacts are not.
- If you ever find the webterm access key value, a password, or a token in
  the staged/committed set, stop and tell the user before doing anything
  else with the repo.
